# 变焦动画相机 - 开发规划文档（修订版）

> 项目基线文档。基于上一轮规划，在曲线编辑器模块新增「变焦点驱动变焦」功能。
> 本文件为开发骨架的参照来源；如有修订请同步更新此处。

## 一、项目概述

### 1.1 产品定位

一款面向普通用户的移动应用，通过屏幕层面的缩放动画技术，为照片和视频添加专业的变焦动画效果。用户可拍摄素材、编辑变焦曲线、实时预览效果，并导出带变焦效果的视频作品。

### 1.2 核心能力边界

- 不能控制：手机摄像头的真实光学/数码变焦参数
- 能够实现：拍摄后的屏幕层面缩放动画处理

### 1.3 目标用户

- 普通用户（非专业摄影师）
- 内容创作者、短视频爱好者
- 希望为作品添加电影感变焦效果的用户

## 二、功能模块规划

### 2.1 拍摄模块

功能描述：调用手机相机进行拍摄，支持手动变焦构图。

核心功能：

- 相机权限申请与管理
- 实时预览取景画面
- 双指捏合/滑块控制预览缩放（仅影响取景构图，不改变实际光学变焦）
- 拍照功能（保存原始分辨率照片）
- 录像功能（保存原始视频素材）
- 闪光灯/对焦/曝光基础控制
- 前后摄像头切换

技术要点：

- 使用 Camera API / CameraX（Android）或 AVFoundation（iOS）
- 预览缩放通过 SurfaceView/TextureView 的矩阵变换实现
- 保存原始素材，不应用任何实时滤镜

### 2.2 曲线编辑器模块（新增「变焦点驱动变焦」功能）

功能描述：可视化编辑变焦动画曲线，支持以用户指定的变焦点为锚点，展开一系列变焦动画效果。

核心功能：

- 时间轴可视化展示
- 关键帧添加/删除/拖拽调整
- 曲线类型选择（线性、缓入、缓出、缓入缓出、贝塞尔曲线）
- 多段曲线支持（可添加多个变焦阶段）
- 缩放比例范围设置（0.5x - 3.0x 或自定义）
- 实时预览当前曲线效果
- 撤销/重做操作

⭐ 新增：变焦点驱动变焦功能

（1）变焦点选择/标记

- 用户在素材画面上点击或拖拽选择变焦点（Focal Point），即动画的锚定中心
- 可视化标记：以选定点为中心显示十字准星或圆形标记
- 支持拖拽调整变焦点位置
- 支持多点变焦点（可设置多个关键变焦点，实现画面在不同点之间切换聚焦）

（2）以变焦点为中心的缩放动画逻辑

- 所有缩放动画以变焦点为变换中心，而非画面中心
- 缩放时画面内容围绕变焦点进行放大/缩小，保持该点在画面中的相对位置
- 数学实现：通过 Canvas 矩阵变换，先平移使变焦点移至原点，执行缩放，再平移回原始位置：`translate(-fx, -fy) → scale(s) → translate(fx, fy)`
- 支持变焦点的平滑移动（从变焦点 A 缓慢移动到变焦点 B，同时执行缩放）

（3）关键帧与变焦点的关联机制

- 关键帧数据结构扩展：`{ time: number, scale: number, easing: string, focalPoint: { x: number, y: number } }`
- 每个关键帧可独立设置变焦点位置
- 相邻关键帧之间的变焦点位置自动插值，实现平滑的焦点移动
- 时间轴上显示变焦点位置变化的辅助轨道
- 支持锁定变焦点（多关键帧共用同一变焦点）或自由调整（每关键帧独立变焦点）

曲线预设模板：

| 预设名称 | 描述 | 适用场景 |
| --- | --- | --- |
| 电影推拉 | 缓慢推近，模拟电影镜头语言 | 人物特写、情感表达 |
| 呼吸变焦 | 轻微周期性缩放，营造呼吸感 | 氛围渲染、艺术短片 |
| 冲击缩放 | 快速推近后定格，强调重点 | 产品介绍、转场效果 |
| 平滑拉远 | 从特写逐渐拉远到全景 | 场景交代、结尾收束 |
| 心跳节奏 | 跟随音乐节拍的缩放律动 | 音乐视频、节奏剪辑 |

技术要点：

- 使用 Canvas 或 SVG 绘制曲线编辑器
- 关键帧数据结构扩展支持变焦点坐标
- 插值算法实现平滑过渡（包括缩放和变焦点位置）
- 矩阵变换实现以任意点为中心的缩放：`translate(-fx, -fy) → scale(s) → translate(fx, fy)`

### 2.3 效果预设库模块

功能描述：提供多种预设变焦效果，一键应用到素材。

核心功能：

- 预设效果分类浏览（电影、Vlog、艺术、节奏）
- 一键应用预设到当前素材
- 预设参数可微调（基于预设进行个性化调整）
- 用户可保存自定义预设
- 预设预览缩略图（静态或动态预览）

### 2.4 导出模块

功能描述：将编辑好的变焦动画导出为视频文件。

核心功能：

- 多种分辨率选择（720p、1080p、4K）
- 多种帧率选择（24fps、30fps、60fps）
- 视频编码格式选择（H.264、H.265）
- 导出进度显示
- 后台导出（应用切到后台继续导出）
- 导出完成后分享功能

### 2.5 素材管理模块

功能描述：管理用户的素材和项目。

核心功能：

- 本地历史记录列表
- 项目草稿保存与恢复
- 批量导出
- 素材导入（从相册导入照片/视频）
- 删除/重命名项目

## 三、技术架构

### 3.1 技术栈

- 跨平台框架：React Native / Flutter（推荐 Flutter，性能更优）
- 视频处理：FFmpeg（移动端移植版）
- 图像处理：OpenGL ES / Metal（iOS）/ Vulkan（Android）
- 状态管理：Redux / Provider
- 本地存储：SQLite / Hive

### 3.2 核心算法

- 变焦动画插值算法（线性、贝塞尔曲线）
- 以变焦点为中心的矩阵变换算法
- 视频帧渲染管线

### 3.3 性能优化

- 离屏渲染预览
- 帧缓存池
- 渐进式导出

## 六、构建与部署方案

### 6.1 不在本地构建原则

为确保构建环境的一致性和可复现性，禁止在本地开发机器上进行生产构建。所有构建工作统一在云端 CI/CD 环境中完成，避免以下问题：

- 本地环境差异导致的"在我机器上能跑"问题
- 开发人员本地依赖版本不一致
- 构建产物无法追溯和审计
- 本地构建配置泄露敏感信息

### 6.2 GitHub Actions 构建流水线

采用 GitHub Actions 作为唯一的构建平台，配置多阶段流水线：

| 阶段 | 触发条件 | 输出产物 |
| --- | --- | --- |
| 代码检查 | PR 创建 / Push 到任意分支 | Lint 报告、Type 检查结果 |
| 单元测试 | PR 创建 / Push 到 develop | 测试覆盖率报告 |
| 集成测试 | PR 合并前 / Push 到 main | E2E 测试报告 |
| 构建打包 | Push 到 main / 打 Tag | Android APK/AAB、iOS IPA |
| 发布部署 | 打 Release Tag | 应用商店分发、GitHub Release |

GitHub Actions 工作流配置要点：

- 环境隔离：使用 GitHub-hosted runners（ubuntu-latest / macos-latest），确保每次构建都是干净环境
- 缓存策略：配置 Gradle、CocoaPods、Flutter SDK 缓存，减少重复下载时间
- 密钥管理：使用 GitHub Secrets 存储签名证书、API Key、发布令牌，禁止硬编码
- 产物保留：构建产物通过 artifacts 上传，保留 30 天供调试使用
- 并行构建：Android 和 iOS 构建任务并行执行，缩短整体耗时

### 6.3 开发一次完成原则

追求开发一次完成，即代码合并到主分支后无需返工。通过以下机制保障：

- 分支保护：main 分支禁止直接推送，必须通过 PR 合并
- 代码审查：所有 PR 需至少 1 人审查通过，重点关注业务逻辑正确性
- 自动化门禁：PR 合并前必须通过所有 CI 检查（Lint、测试、构建）
- 预提交钩子：本地配置 husky + lint-staged，提交前自动格式化代码
- 单测覆盖率门槛：核心模块覆盖率不低于 80%，新代码覆盖率不低于 90%

## 七、质量保证与 Bug 防控

### 7.1 严格检查 Bug 策略

建立多层级的 Bug 防控体系，将问题拦截在发布之前。

代码层面检查：

- 静态分析：集成 Dart Analyzer / ESLint / SonarQube，检测潜在空指针、未使用变量、复杂度过高
- 类型检查：启用严格模式（strict mode），编译期捕获类型错误
- 代码格式化：统一使用 dartfmt / Prettier，避免格式争议
- 依赖审计：定期运行 `flutter pub outdated` 和 `npm audit`，及时更新有漏洞的依赖

测试层面检查：

- 单元测试：核心算法（变焦插值、矩阵变换）必须有单测覆盖
- Widget 测试：UI 组件交互逻辑验证
- 集成测试：模块间协作验证（拍摄→编辑→导出流程）
- 设备兼容性测试：覆盖主流 Android 机型（API 24+）和 iOS 设备（iOS 14+）
- 性能测试：导出 1080p 视频内存占用不超过 500MB，4K 导出不超过 1GB

人工层面检查：

- 代码审查清单：Reviewer 必须对照检查清单逐项确认
  - 业务逻辑是否符合需求
  - 边界条件是否处理（空值、越界、异常）
  - 资源是否正确释放（内存、文件句柄）
  - 并发场景是否安全
  - 是否有潜在性能问题
- 冒烟测试：每次构建后执行核心功能验证（拍摄→添加变焦点→导出）
- Beta 测试：发布 TestFlight / Firebase App Distribution 给内部用户试用

### 7.2 Bug 分级与响应机制

| 级别 | 定义 | 响应时间 | 处理方式 |
| --- | --- | --- | --- |
| P0 - 致命 | 应用崩溃、数据丢失、无法启动 | 2 小时内 | 立即修复，热更新或紧急发版 |
| P1 - 严重 | 核心功能不可用（拍摄失败、导出失败） | 24 小时内 | 优先修复，下个版本必须解决 |
| P2 - 一般 | 功能异常但有 workaround | 3 天内 | 排期修复 |
| P3 - 轻微 | UI 瑕疵、文案错误 | 1 周内 | 随版本迭代修复 |
